# TaskManager

TaskManager — учебное SPA-приложение для личного и командного управления задачами и проектами.

Проект предназначен для закрепления навыков работы с React: компонентный подход, маршрутизация, локальное и глобальное состояние, CRUD-операции, работа с REST API, клиентская валидация форм и модульная стилизация.

## Функциональность

### Авторизация

- регистрация нового пользователя;
- вход по email и паролю;
- выход из аккаунта;
- сохранение текущей сессии в `localStorage`;
- защита приватных маршрутов через `ProtectedRoute`.

Авторизация реализована как учебная mock-реализация. Пользователи хранятся в `db.json`, а пароль в этой учебной версии хранится открытым текстом. Для production-приложения потребовались бы серверное хеширование паролей и полноценная система аутентификации.

Демо-аккаунт:

```text
Email: demo@taskmanager.local
Password: demo123
```

### Задачи

Для основного объекта приложения — задачи — реализованы CRUD-операции:

- создание;
- получение и отображение;
- редактирование;
- удаление.

Задача содержит:

- название;
- описание;
- статус;
- приоритет;
- проект;
- автора;
- срок выполнения;
- дату создания и обновления;
- комментарии;
- метаданные прикреплённых файлов.

Автор задачи определяется автоматически из текущей авторизованной учётной записи.

Статусы:

- `To Do`;
- `In Progress`;
- `Done`.

Приоритеты:

- `Low`;
- `Medium`;
- `High`.

### Фильтрация и сортировка

На странице задач доступны:

- поиск по названию, описанию и автору;
- фильтрация по статусу;
- фильтрация по приоритету;
- фильтрация по проекту;
- фильтрация по автору;
- сортировка по дате создания;
- сортировка по названию;
- сортировка по приоритету;
- сортировка по сроку выполнения.

Фильтрация и сортировка выполняются на клиентской стороне. Для мемоизации результата используется `useMemo`.

### Проекты

Для проектов реализован отдельный CRUD:

- создание;
- получение и отображение;
- редактирование;
- удаление;
- название, описание и цвет проекта;
- количество задач;
- процент выполненных задач.

Удаление проекта блокируется, если к нему привязаны задачи.

### Комментарии

На странице задачи можно добавлять комментарии.

Комментарий проходит клиентскую валидацию через React Hook Form и Zod. Проверяется наличие текста и ограничение в 500 символов.

### Прикрепление файлов

В приложении используется браузерный File API. При выборе файла сохраняются его метаданные:

- имя;
- размер;
- MIME-тип.

Физическая загрузка файла на сервер в учебной версии не выполняется. В `db.json` сохраняются только метаданные.

## Архитектура

Проект реализован по модульному компонентному принципу.

```text
src/
├── components/
│   ├── auth/
│   ├── layout/
│   ├── projects/
│   ├── tasks/
│   └── ui/
│
├── hooks/
│   ├── useAuth.js
│   ├── useProjects.js
│   └── useTasks.js
│
├── pages/
│   ├── Auth/
│   ├── Dashboard/
│   ├── NotFound/
│   ├── Projects/
│   └── Tasks/
│
├── services/
│   └── api.js
│
├── store/
│   ├── useAuthStore.js
│   ├── useProjectStore.js
│   └── useTaskStore.js
│
├── styles/
│   └── global.css
│
├── utils/
│   ├── constants.js
│   └── formatters.js
│
├── validation/
│   ├── authSchema.js
│   ├── commentSchema.js
│   ├── projectSchema.js
│   └── taskSchema.js
│
├── App.jsx
└── main.jsx
```

### `pages`

Содержат страницы приложения и связывают между собой компоненты, хуки и сценарии пользователя.

### `components`

Содержат переиспользуемые UI-компоненты: таблицу задач, фильтры, формы, карточки проектов, кнопки и компоненты состояний.

### `hooks`

Предоставляют удобный интерфейс для работы страниц с глобальным состоянием Zustand.

### `store`

Содержит глобальное состояние приложения на базе Zustand: авторизацию, задачи и проекты.

### `services`

Содержит HTTP-запросы к учебному REST API. Для запросов используется встроенный Fetch API.

### `validation`

Содержит схемы клиентской валидации на базе Zod.

### `utils`

Содержит общие константы и функции форматирования дат и размеров файлов.

## SPA и маршрутизация

Приложение работает как Single Page Application. В `main.jsx` подключён `BrowserRouter`, а маршруты описаны через `Routes` и `Route`.

Основные маршруты:

```text
/login
/register
/
/tasks
/tasks/new
/tasks/:taskId
/tasks/:taskId/edit
/projects
```

Переходы между страницами выполняются через React Router без полной перезагрузки браузера.

Приватные маршруты защищены компонентом `ProtectedRoute`. Неавторизованный пользователь перенаправляется на `/login`.

## Управление состоянием

### Локальное состояние

Для состояния конкретного компонента используется `useState`.

Например:

- состояние фильтров;
- открытие формы проекта;
- состояние отправки формы;
- текст комментария;
- состояние подтверждения удаления.

### Глобальное состояние

Для данных, которые используются разными страницами и компонентами, используется Zustand.

Основные store:

- `useAuthStore` — текущий пользователь и сессия;
- `useTaskStore` — задачи и операции CRUD;
- `useProjectStore` — проекты и операции CRUD.

## Работа с API

В качестве учебного backend используется `json-server`.

```text
http://localhost:3001
```

Основные HTTP-методы:

```text
GET     получение данных
POST    создание данных
PUT     обновление данных
DELETE  удаление данных
```

Основная цепочка работы с данными:

```text
React-компонент
      ↓
hook
      ↓
Zustand store
      ↓
services/api.js
      ↓
Fetch API
      ↓
json-server
      ↓
db.json
```

## Валидация форм

Для форм используется связка:

```text
React Hook Form + Zod
```

Валидация реализована для:

- входа;
- регистрации;
- создания и редактирования задачи;
- создания и редактирования проекта;
- добавления комментария.

Ошибки отображаются непосредственно рядом с соответствующими полями или в UI-сообщениях об ошибке операции.

## Стилизация

Для стилизации используются CSS Modules и глобальные CSS-переменные.

Каждый крупный компонент имеет собственный модуль стилей, например:

```text
Button.module.css
TaskTable.module.css
TaskForm.module.css
ProjectCard.module.css
```

Это изолирует стили компонентов и уменьшает вероятность конфликтов CSS.

## Ограничения учебной реализации

Проект предназначен для демонстрации навыков React и не является production-системой.

Основные ограничения:

- авторизация является mock-реализацией;
- пароль хранится в `db.json` открытым текстом;
- нет JWT или серверных session cookies;
- права доступа не проверяются на сервере;
- физические файлы не загружаются на сервер;
- `json-server` используется как учебный backend.

Для production-версии потребовались бы настоящий backend, база данных, безопасное хранение паролей, серверная проверка прав доступа и файловое хранилище.
